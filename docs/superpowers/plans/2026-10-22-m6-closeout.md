# OneFilm M6 收尾 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在保留可回滚路径的前提下完成 TV Compose UI 的回归、旧 UI 删除、测试/截图基线和发布合规，产出可发布的 TV Release。

**Architecture:** 先建立可重复验证（单元测试、Compose instrumentation、截图、真机矩阵），再关闭 `compose_ui` fallback，最后按依赖清单分批删除旧 TV XML/Fragment/Activity。旧播放器、直播、文件选择等仍有运行时用途的 bridge 和 Activity 不删除；手机旧 UI 是否删除单独立项，不与 TV 收尾混在一起。

**Tech Stack:** Kotlin 2.3 / Jetpack Compose（BOM 2026.09）/ Navigation Compose / FongMi PlayerManager / Media3+MPV / Gradle 9.7.1 / AGP 9.3.1 / JDK 21。

**Spec:** `docs/2026-10-21-project-status.md`、`docs/compose-ui-roadmap.md`

## Global Constraints

- 真机 TV 矩阵未通过前，不删除 `compose_ui` fallback，不删除 TV `HomeActivity`。
- 删除旧 UI 必须分批，每批后跑 `:app:assembleLeanbackDebug`；不得一次性删除整个 `ui` 包。
- 保留仍有运行时引用的组件：`LiveActivity`、`VideoActivity`、`PlaybackActivity`、`FileActivity`、`AppLegacyPlayer`、`AppLiveLauncher`、`AppFileLauncher`、`DetailLauncher`（按引用审计结果决定）。
- 所有提交标题和说明使用中文；默认只提交本地，不 push。
- TV Release 只使用 Release APK 做体验和性能验证；Debug APK 只用于开发。
- 每次删除/覆盖前先列清单；无法验证的项标注“未验证”，不得写成“完成”。

## Review Focus

- 焦点从主页分类向下到“历史”后，再向下必须进入海报区，不能反复被分类层截获。
- 分类快速右移时，最后一次焦点必须落在最后经过的分类，不能回跳旧分类或落入海报区。
- 卡片放大时必须只改内部绘制层，外部语义 bounds 和相邻卡片位置不变。
- 删除旧 UI 后，直播/旧播放器/文件选择等运行时入口仍必须可用。
- Release 混淆后仍能启动、加载配置、搜索、详情和播放，不能被 R8 裁掉反射/JNI 类。
