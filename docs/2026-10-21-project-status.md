## 1. 结论

Compose UI 功能开发基本结束，项目已进入 **M6 收尾阶段**。当前重点从“做功能”转为“可验证、可发布、可回滚”。

| 阶段 | 进度 | 结论 |
|---|---|---|
| P0 基础/身份/构建 | 100% | 两 flavor 可构建，Compose 宿主机和旧 UI fallback 已建立 |
| M1 基础设施 | 100% | 设计系统、Bridge、导航、首页骨架完成 |
| M2 数据接入 | 100% | 首页、分类、搜索、详情、收藏、历史、网盘已接真实数据与持久化缓存；来源页统一进入 Compose 详情，旧 DetailLauncher 兜底已移除 |
| M3 Compose 播放器 | 100% | 旧 PlayerManager 内核、全屏隐藏控件 seek/暂停/继续、进度条焦点全部完成；TV 底部精简条/右侧面板 UI 未优化，按要求保留现状；手机手势按要求暂不测试 |
| M4 设置页 | 97% | 播放/解码/字幕/弹幕/预加载/接口/主题/二维码推送、播放超时已完成；代理/Hosts 由接口 JSON 配置；手机设置滚动暂不测试 |
| M5 TV 回归 | 98% | 真机 Release；主页向下、分类快速右移、卡片放大不位移、历史/搜索返回焦点、设置首项/返回、隐藏态 seek/暂停、暂停后确认继续全部通过 |
| M6 收尾 | 85% | 已完成测试、真机核心矩阵、截图基线、发布文档、NOTICE、性能/无障碍初始基线；HomeActivity 已删除，SEARCH/SEND/VIEW 已迁移；剩余旧 Fragment/XML 与完整性能测量 |

总体判断：**M1/M2 完成，M3/M4/M5 主体完成（手机项按要求暂不测试），M6 仍有旧 Fragment/XML 与完整性能测量收尾。**
当前最大风险已经变成 **旧 UI 删除的回归缺口** 和 **TV 真机未完成系统化回归**；卡片缩放/主页向下焦点这两个高频问题已在模拟器闭环。

## 6. M6 执行顺序

1. **先补可重复验证**：修 instrumentation 测试、加焦点/缩放回归测试、建立截图基线。
2. **TV 真机矩阵**：首页 → 分类 → 搜索 → 详情 → 播放 → 设置 → 返回；通过前不删旧 UI。
3. **分批删除旧 UI**：先移除 `compose_ui` 开关和 TV `HomeActivity` 入口，再按依赖清单删除 XML/Fragment/Activity。
4. **清理 bridge**：只删除无引用桥；保留仍承载旧播放器/直播/文件选择的桥。
5. **发布合规**：LICENSE/NOTICE/版权页/版本说明/源码 tag。
6. **包体与性能**：ABI/R8/图片缓存/首屏帧率/无障碍基线。
7. **补剩余功能缺口**：网络代理/Hosts/超时、TV 控制条、手机手势、声道、DLNA/DV/MPV 长稳。

## 8. 已知测试限制

- 客厅电视 `192.168.1.22:5555` 已恢复在线，Release 已安装；其余矩阵继续在真机执行。
- 手机 `e1096c9` 未连接。
- x86 模拟器缺少部分 ARM 原生库，分类页二次加载、详情播放/蜘蛛可能报 `EM_ARM` 或 Chaquopy 原生库错误；分类滚动与播放器矩阵以真机为准。
- 详情/播放器包含视频 Surface，`uiautomator dump` 可能因持续渲染无法 idle；这类项需用遥控器操作 + 截图/日志验证。
- 模拟器触摸操作会进入 touch mode，程序化焦点请求不稳定；方向键测试更接近真实遥控器。
- 因此，本文件中的“已完成”以代码和构建/模拟器证据为准；真机焦点与播放稳定性必须单独回归。
